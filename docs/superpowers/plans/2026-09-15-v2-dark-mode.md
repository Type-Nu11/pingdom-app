# V2 Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add persisted SYSTEM/LIGHT/DARK appearance selection and a complete semantic light/dark theme to production-reachable V2 UI without remounting application state.

**Architecture:** A pure appearance model and AsyncStorage service feed a minimal Zustand preference/hydration store. A common provider derives the resolved scheme from the current React Native system scheme, constructs the active styled theme, and synchronizes app-owned native/navigation surfaces.

**Tech Stack:** React Native 0.83, Expo 55, TypeScript, styled-components 6, Zustand 5, AsyncStorage 2.2, React Navigation 7, Jest/RNTL.

**Spec:** `docs/superpowers/specs/2026-09-15-v2-dark-mode-design.md`

## Global Constraints

- Implement in V2 plus the shared application composition boundary; V1 dependency delta stays `none`.
- Add no package and do not commit or push.
- Do not store theme objects or system scheme in Zustand; derive resolved scheme from preference and live system value.
- Never render a forced light app frame before appearance hydration; read failure or timeout must release the boot gate.
- Do not change map query, ranking, sorting, filtering, gestures, animation, or #318 recommendation data flow.
- Do not claim automated WCAG AA coverage for combinations that were not measured.
- Change `app.json` to `userInterfaceStyle: automatic`; avoid Expo Prebuild regeneration and large native diffs.
- Preserve the current #319 settings navigation and add only its reachable appearance detail.
