# 지도 피드·장소 상세 렌더링 실측 (#458)

2026년 11월 24일에 #452가 반영된 `dev` `1b890f60`을 기준으로 측정했다. 두 빌드의 사용자 기능 차이는 장소 상세 리뷰 탭의 가로 사진 모음에 `FlatList`를 적용한 부분이다.

## 측정 환경

- 갤럭시 노트20 5G (SM-N981N), Android 13, 1080 × 2400, 60Hz. USB 연결 상태에서 측정했고 Android 열 상태는 정상(0)이었다.
- 같은 Android arm64 Release 설정과 Hermes를 사용했다. 두 APK에 동일한 React 커밋 계측과 개발용 모의 API를 포함했다. 위치는 진주시로 고정했고 사진은 USB 역방향 연결의 로컬 HTTP 서버에서 제공했다.
- 핫플·전국 트렌드 응답 각각 20곳을 제공했다. 선택한 장소에는 본문 사진 12장과 리뷰 20개, 리뷰당 사진 3장(사진 모음 60장)을 사용했다. 일부 이미지 요청은 지정한 404를 반환한다. 이미지 원본은 1600 × 1200 JPEG 테스트 패턴이다.
- 각 동작 직전에 `adb shell dumpsys gfxinfo com.rmdka.pingdomapp reset`을 실행했다. 동작과 정해진 대기 후 `gfxinfo … framestats`를 저장했다. 표의 p95와 지연 프레임 비율은 Android가 보고한 값이다.
- 각 동작 전후의 `adb shell dumpsys meminfo com.rmdka.pingdomapp`에서 앱 프로세스 전체 PSS를 읽었다. 이미지 캐시를 지우지 않았고 리뷰 진입은 정보 탭으로 돌아간 뒤 총 3회 반복했다. React 커밋은 `useLayoutEffect` 카운터의 구간 차이다. 메모리 숫자는 시점별 스냅샷이다.

## 결과

| 동작 | p95 기준 → 변경 | 지연 프레임 기준 → 변경 | 종료 시 PSS 기준 → 변경 |
| --- | ---: | ---: | ---: |
| 피드 시트 확장 (1회) | 101 → 101ms | 34/37 → 32/35 | 506.9 → 501.8MiB |
| 피드 세로 스크롤 (4회 스와이프) | 30 → 27ms | 12/196 → 16/195 | 498.8 → 495.7MiB |
| 피드에서 장소 미리보기 열기 (1회) | 121 → 93ms | 14/19 → 16/22 | 480.9 → 517.4MiB |
| 장소 상세 확장 (1회) | 109 → 85ms | 15/23 → 18/19 | 538.0 → 526.0MiB |
| 리뷰 탭 진입 (3회 중앙값) | 150 → 121ms | 100% → 100% | 794.5 → 661.4MiB |
| 리뷰 세로 스크롤 (4회 스와이프) | 150 → 77ms | 28/28 → 85/85 | 791.4 → 667.8MiB |

리뷰 탭 진입 후 PSS 중앙값이 **133.1MiB(16.8%) 감소**했다. 진입 직전 대비 PSS 증가분의 중앙값은 **206.9 → 85.5MiB**였다. 같은 구간의 상세 이미지 컴포넌트 커밋 중앙값은 **204 → 162회**였다. 이 카운터에는 본문 사진, 사진 모음 및 개별 리뷰의 이미지 컴포넌트가 포함되고 네이티브 디코드 횟수는 별도다. 리뷰 행 커밋 중앙값은 **40 → 46회**였다.

리뷰 탭 진입은 샘플당 프레임이 5~13개였고, 동일 기기에서 순차 실행해 캐시와 GC 상태를 통제하지 않았다. 피드·미리보기·상세 확장의 전후 편차는 각 1회 측정 결과다. 리뷰 탭에서 감소한 PSS는 세 번 모두 관찰됐다. 리뷰 탭과 세로 스크롤에서 여전히 모든 프레임이 Android의 마감 시간 기준을 놓쳤다.

## 적용 범위와 회귀 확인

- 리뷰 사진 모음의 가로 목록에 `FlatList`를 사용해 처음 6장을 렌더링하고 스크롤 위치에 따라 주변 항목을 추가한다. 사진 뷰어에는 전체 배열과 누른 사진의 원래 인덱스를 넘긴다. 세로 상세 스크롤과 시트 제스처는 기존 구성을 유지한다.
- Android 실기기에서 시트 확장, 피드와 리뷰 세로 스크롤, 장소 선택, 404 대체 표시, 가로 스크롤 후 9번째 사진 열기를 확인했다. 사진 뷰어에 `9 / 60`이 표시됐고 접근성 노드에도 `사진 60장 중 9번째`가 노출됐다.
- 피드는 화면에서 가로 최대 6개와 그리드 최대 8개로 제한된다. 피드 시트 확장 p95는 두 빌드에서 101ms로 같았고, 이 변경은 리뷰 사진 모음에 한정했다. 상세 스크롤에 포함된 개별 리뷰 행과 이미지 스트립의 비용은 남아 있다.
- iOS 실측은 하지 않았다. 화면 읽기 검증 범위는 Android 접근성 트리의 레이블과 순서 표시다. V1 의존성 변경은 `none`이다.
- Android의 전환 및 Animator 배율을 0으로 설정했을 때도 시트 확장, 두 번째 장소 선택 및 리뷰 탭의 404 표시를 확인했다. 테스트 후 원래 배율로 복원했다.
- `npm run check:v2`, `npm run typecheck`, `npm run test:v2-map`(51개)과 `npm test -- --runInBand --no-watchman MapBottomSheet MapSheetSurface PlacePhotoViewer useReducedMotion`(103개)이 통과했다. 리뷰 사진 모음에서 선택한 인덱스의 사진을 여는 회귀 테스트를 추가했다.
