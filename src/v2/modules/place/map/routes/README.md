# 앱 내부 길찾기 준비

서버 의존 이슈: https://github.com/Type-Nu11/pingdom-api/issues/1735

## 현재 동작

- 기존 핑덤 장소 목록 검색 API로 출발지와 목적지를 선택합니다. 텍스트만으로 좌표를 추정하지 않습니다.
- 현재 위치는 위치 권한과 연결됩니다. 직접 선택한 출발지는 위치 권한 없이 사용할 수 있습니다.
- 출발/도착 교환 시 이름과 좌표를 함께 교환합니다.
- 경로 공급자 미연결 상태에서는 거리나 ETA를 계산하지 않습니다. 선택한 이동수단으로 네이버 지도 앱을 엽니다.
- 미설치 시 사용자 선택으로 스토어 또는 목적지 공유를 제공합니다. 실행 오류는 재시도 가능한 안내로 표시합니다.
- Android/iOS 지도 브리지의 `routeCoordinates`가 좌표열을 그립니다. 빈 배열은 이전 선을 제거합니다. 출발/도착 마커에 캡션을 표시합니다.
- 전체 경로 좌표를 기준으로 화면 크기에 맞춰 카메라를 계산합니다. 지도와 결과 패널은 공간을 분리하여 경로가 패널 아래에 가려지지 않습니다.

## 개발용 검증

`__DEV__`이면서 `EXPO_PUBLIC_APP_ENV=development`인 경우에만 ‘경로’ 제목을 길게 눌러 예시 제어를 표시할 수 있습니다. 예시 버튼을 명시적으로 눌러야 활성화됩니다.

- 예시 경로 보기: 고정된 시청→청계광장 좌표와 합성 결과를 사용합니다. 실제 보행 경로/소요시간이 아닙니다.
- 예시 경로는 실제 선택 장소의 경로로 사용하지 않으며, 외부 지도 실행도 비활성화합니다.
- 경로 없음/오류 상태와 재시도를 확인할 수 있습니다. 예시 종료는 원래 장소 선택을 복원합니다.
- production/staging 및 릴리스 빌드에는 예시 제어가 표시되지 않습니다.

## 서버 계약 확정 후

`routePreparation.ts`는 프론트 내부 모델이며 서버 DTO가 아닙니다. 서버 계약 확정 후 별도 매핑을 통해 경로 좌표와 결과 카드를 공급합니다. 요청 취소 및 이전 응답 무시는 실제 데이터 조회 계층에서 구현해야 합니다. 대중교통 구간별 표시와 지원 이동수단은 최종 계약에 맞춥니다.

## 검증 범위

타입 검사, V2 경계 검사, 지도 회귀 테스트, 길찾기·번역·화면 테스트와 Android Kotlin 컴파일을 수행합니다. 네이티브 속성과 앱 조회 설정이 추가되어 개발 앱 재빌드가 필요합니다.
iOS 빌드와 양쪽 기기에서의 지도 렌더링/외부 앱 이동 확인은 별도 필요합니다. 이번 환경은 iOS 26.2 플랫폼 부재로 Xcode 빌드를 실행하지 못했습니다.

V1 dependency delta: `none`.
